# Как пополнять examples/ и что это даёт

## Структура

```
examples/
  gas/01/input/*.jpg      скан эскиза
  gas/01/result/*.dwg     ваш готовый чертёж по этому эскизу
  gas/01/model.json       (сильно желательно) разбор эскиза
  gas/01/notes.md         (по желанию) что важно в примере
```

Тип сети — имя папки. Он же попадает в `network_type` и определяет
оформление.

## Индексация

```powershell
$env:PYTHONPATH = "$PWD\.pydeps"
python tools\index_examples.py
```

Скрипт:

1. находит пары `input/` + `result/`;
2. конвертирует каждый `result/*.dwg` в DXF (Open CAD Studio `--export`);
3. вытаскивает профиль: слои, цвета, типы линий, блоки, шрифты,
   размерные стили, примеры надписей, габариты;
4. пишет `examples/index.json`.

Профиль подмешивается в промпт распознавания: модель видит, какими слоями,
какими формулировками и каким штампом вы пользуетесь.

## Зачем model.json

`examples/gas/02/model.json` — пример ручного разбора. Такие файлы идут
в промпт как few-shot: «вот эскиз → вот его структура». Один-два
качественных примера дают больше, чем десять сканов без разбора.

Достаточно 5–10 разобранных эскизов, чтобы распознавание стало стабильным.

## Что усиливает пример

* разные почерки и качество сканов;
* `notes.md` с одной-двумя фразами: «длины в мм», «двухтрубная»;
* наличие в `result/` именно того DWG, который вы считаете эталоном
  (он задаёт стиль слоёв и надписей).

## Чего избегать

* одиночные `input/` без `result/` — они почти не влияют;
* переименование папок «на бегу» — индексатор привязывается к номеру;
* PDF-сканы с несколькими листами в одном файле — лучше по одному.

## Проверка

```powershell
python -m netsketch doctor
Get-Content examples\index.json -TotalCount 40
```
