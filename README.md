# NetSketch — чертежи инженерных сетей по рукописным эскизам

Веб-приложение: пользователь выбирает тип сети, загружает скан эскиза,
указывает формат листа и реквизиты — на выходе получает **редактируемый DWG**,
PDF и PNG. Внутри работают модель зрения и детерминированный генератор
чертежей; пользователь с ними не общается.

```
 скан эскиза (JPG/PNG/PDF)
        │
        ▼
 ┌──────────────────┐   model.json   ┌────────────────────┐
 │  распознавание   │ ─────────────► │    черчение        │
 │  (vision-модель, │                │  раскладка листа   │
 │   промпт + база  │                │  слои, символы,    │
 │   знаний + ваши  │                │  легенда, штамп    │
 │   примеры)       │                │  DXF → DWG/PDF/PNG │
 └──────────────────┘                └────────────────────┘
```

Ключевая идея: **модель не рисует линии**. Она только превращает картинку в
структуру (трасса, диаметры, арматура, подписи). Чертит обычный код — поэтому
результат повторяем, лист не «плывёт», а геометрию можно править в AutoCAD
или Open CAD Studio.

## Что получается

| Файл | Назначение |
|---|---|
| `*.dwg` | редактируемый чертёж, слои и подписи настоящие |
| `*.pdf` | лист 1:1 в мм, готов к печати |
| `*.png` | предпросмотр для писем и мессенджеров |
| `*.dxf` | обменный формат, если DWG не нужен |
| `model.json` | разбор эскиза, его можно поправить и пересобрать |

Лист: рамка по ГОСТ (слева 20 мм), основная надпись 185×55, масштаб из ряда
1:50…1:5000, справа — «Условные обозначения», «Спецификация трубопроводов»,
«Примечания». Домысленные данные выносятся на слой `ASSUMED` и в примечания.

Геометрия нормализуется: рукописная дрожь убирается, газовые трассы
доводятся до прямых участков и поворотов 90°, тепловые сохраняют настоящие
диагонали. Труба не гнётся — см. `netsketch/route.py`.

## Быстрый старт

```powershell
# 1. зависимости (в папку проекта, системный Python не трогаем)
python -m pip install --target .pydeps -r requirements.txt

# 2. настройки
copy .env.example .env    # вписать ключ vision-модели

# 3. запуск
run.cmd                   # или: python -m netsketch serve
```

Откроется `http://127.0.0.1:8770`. Дальше: тип сети → эскиз → лист →
реквизиты → «Создать чертёж».

Проверка окружения и сборка без браузера:

```powershell
$env:PYTHONPATH = "$PWD\.pydeps"
python -m netsketch doctor
python -m netsketch build examples\gas\02\model.json --out output --stem gas02
python tools\smoke_test.py
```

Требуется **Open CAD Studio** (для DXF → DWG). Путь ищется автоматически,
иначе задайте `NS_OCS_EXE`.

## Распознавание: какой нужен провайдер

Нужна **vision-модель** (принимает изображения). Подходит любой
OpenAI-совместимый endpoint:

```ini
NS_LLM_PROVIDER=openai
NS_LLM_BASE_URL=https://api.openai.com/v1
NS_LLM_MODEL=gpt-4.1
NS_LLM_API_KEY=sk-…
```

Готовые пресеты: `openai`, `openrouter`, `gemini`, `ollama`, `custom`.
Локально: `NS_LLM_PROVIDER=ollama`, `NS_LLM_MODEL=qwen2.5vl:7b`.

> **Важно:** DeepSeek API (`deepseek-chat`) изображения не принимает, поэтому
> распознавание на нём не заработает. DeepSeek хорош для текстовых этапов.

### Тихий режим без ключа (ручной/агентский)

Если ключа нет, задача встаёт в статус «Нужно распознавание»:

1. в `data/jobs/<id>/` появляются `prompt_system.txt`, `prompt_user.txt`;
2. эскиз разбирает человек или агент и кладёт `model.json`;
3. `POST /api/jobs/<id>/model` — и чертёж собирается.

Для полностью автоматического режима есть `NS_LLM_COMMAND`: команда получает
папку задачи (`NS_JOB_DIR`) и должна положить в неё `model.json`. Так можно
подключить свой headless-агент, локальный пайплайн или корпоративный шлюз —
пользователь всё равно видит только веб-форму.

## Примеры: как научить систему вашему стилю

```
examples/gas/01/input/*.jpg     скан
examples/gas/01/result/*.dwg    ваш готовый чертёж
examples/gas/01/model.json      (желательно) разбор эскиза
```

```powershell
python tools\index_examples.py
```

Индексатор конвертирует ваши DWG в DXF, вытаскивает слои, цвета, типы линий,
шрифты, примеры надписей и штамп — и складывает всё в `examples/index.json`.
Этот профиль подмешивается в промпт, а `model.json` из примеров работает как
few-shot. Подробнее — `examples/README.md` и
`skills/utility-network-drawing/references/examples-guide.md`.

## Скиллы для агентов (необязательно)

Продукту скиллы не нужны: правила живут в `knowledge/` и промптах, чертит код.
Скиллы нужны человеку или агенту, который будет проект дорабатывать либо
разбирать эскизы вручную (режим «Нужно распознавание»).

| Скилл | Зачем |
|---|---|
| `skills/utility-network-drawing/` | цикл «эскиз → model.json → DWG/PDF/PNG» |
| `skills/gost-drafting/` | рамка, штамп 185×55, печать A4, аннотации исполнительной схемы |
| `skills/gost-gas-documentation/` | СПДС: ГОСТ 21.609-2014 (внутренние системы) и ГОСТ 21.710-2021 (наружные сети) — обозначения, состав листа, примеры |

Чтобы скиллы подхватывались автоматически в сессиях DSH, поставьте их в
профиль:

```powershell
powershell -ExecutionPolicy Bypass -File tools\install_skill.ps1
# только один скилл:
powershell -File tools\install_skill.ps1 -Skill gost-gas-documentation
# или ссылкой, чтобы правки в репозитории подхватывались сразу:
powershell -File tools\install_skill.ps1 -Link
```

Дальше достаточно сказать агенту «собери чертёж по эскизу» — он загрузит
скилл и пойдёт по описанному циклу.

## Перенос на другой компьютер

Код и все накопленные знания о проекте лежат в git, этого достаточно:

```powershell
git clone git@github.com:tdutanton/utility-network-recreation.git
cd utility-network-recreation
python -m pip install --target .pydeps -r requirements.txt
copy .env.example .env        # вписать ключ модели
powershell -File tools\install_skill.ps1
run.cmd
```

Что **не** переносится намеренно:

| Что | Почему | Как быть |
|---|---|---|
| `.env` | секрет, в git не хранится | скопировать вручную |
| `.pydeps/` | привязка к интерпретатору | переустановить |
| `data/` | задачи и результаты | генерируются заново |
| Open CAD Studio | отдельная программа | установить, либо `NS_OCS_EXE` |

История диалога DSH — это отдельные файлы в
`%USERPROFILE%\.dsh\sessions\<папка-рабочей-папки>\*.jsonl.zstd`. Их можно
скопировать, если нужен именно чат, но на работу проекта они не влияют:
всё существенное для черчения зафиксировано в репозитории.

## HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | состояние: OCR/CAD/очередь |
| GET | `/api/options` | типы сетей, форматы, умолчания |
| POST | `/api/jobs` | создать задачу (файлы в base64) |
| GET | `/api/jobs` | последние задачи |
| GET | `/api/jobs/<id>` | статус, прогресс, лог, файлы |
| POST | `/api/jobs/<id>/model` | передать `model.json` вручную |
| POST | `/api/jobs/<id>/retry` | повторить |
| GET | `/api/jobs/<id>/file/<dwg\|pdf\|png\|dxf>` | скачать |
| GET | `/api/jobs/<id>/prompt` | задание на распознавание |

## Устройство репозитория

```
netsketch/
  config.py      настройки (.env), поиск Open CAD Studio, типы сетей
  model.py       семантическая модель + терпимый разбор JSON
  prompts.py     промпты распознавания
  knowledge.py   загрузка базы знаний и профиля из examples/index.json
  recognize.py   вызов vision-модели, PDF→PNG, разбор ответа
  route.py       геометрия трассы: прямые участки и повороты 90°
  layout.py      раскладка: масштаб, план, легенда, спецификация, примечания
  sheets.py      форматы, рамка, основная надпись
  symbols.py     условные обозначения
  styles.py      слои, типы линий, стили
  scene.py       примитивы в мм листа
  dxfout.py      сцена → DXF
  render.py      сцена → PDF/PNG
  dwg.py         DXF → DWG (Open CAD Studio)
  build.py       сборка комплекта файлов
  qa.py          проверки результата
  jobs.py        очередь и хранилище задач
  pipeline.py    эскиз → модель → чертёж
  server.py      HTTP API + статика
  cli.py         командная строка
web/             интерфейс (HTML/CSS/JS без сборки)
knowledge/       общие правила, газ, тепло (идут в промпт и в документы)
examples/        ваши пары «эскиз → DWG»
skills/          скиллы для агентов DSH
tools/           индексатор примеров, смоук-тест, API-тест, демо
data/            задачи и результаты (в git не попадает)
```

## Добавить новый тип сети

1. `knowledge/<тип>.md` — что искать на эскизе и как оформлять.
2. `styles.NETWORK_LAYERS[<тип>]` + ветка в `styles.layer_of`.
3. `config.BUILTIN_NETWORK_TYPES[<тип>]` — подпись и шифр дисциплины.
4. При необходимости — символы в `symbols.draw_symbol`.

Интерфейс подхватит тип сам (список приходит из `/api/options`).

## Ограничения текущей версии

* Один лист на чертёж; многостраничные PDF разбираются по первой странице.
* Распознавание зависит от качества скана; мелкие подписи у края могут
  потеряться — они попадают в «На что обратить внимание».
* Высоты, глубины и материалы не восстанавливаются из плоского эскиза:
  если их нет на листе, они не домысливаются.
* Компоновка «план + правая колонка» — без выносных видов и развёрток.
