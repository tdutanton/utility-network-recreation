# AGENTS.md — правила работы в этом репозитории

## Что это

NetSketch: веб-приложение, которое строит DWG/PDF/PNG по рукописному эскизу
тепловой или газовой сети. Пользователь работает с веб-формой; модель зрения
и генератор чертежей скрыты внутри.

## Быстрый цикл

```powershell
$env:PYTHONPATH = "$PWD\.pydeps"
$env:PYTHONIOENCODING = "utf-8"
python -m netsketch doctor
python tools\smoke_test.py          # ~1 мин, гоняет OCS и режим schematic
python tools\gost_verify.py         # лист ГОСТ: сетка/тексты/углы/печать vs эталон
python tools\recognize_check.py --selftest   # приёмка распознавания (швы, шифр, итог)
python tools\api_test.py http://127.0.0.1:8770
```

Зависимости лежат в `.pydeps` (не в системном Python). Ставятся так:

```powershell
python -m pip install --target .pydeps -r requirements.txt
```

## Инварианты, которые нельзя ломать

1. **Один источник геометрии.** `layout.build_scene()` (план) или
   `layout.build_schematic_scene()` (лист ГОСТ) → `Scene` в мм листа.
   DXF и PDF/PNG строятся только из неё. Нельзя рисовать PDF «отдельно»;
   печатный A4 — это тот же `Scene` после `gost_sheet.print_transform()`.
2. **Единицы — миллиметры листа, 1:1.** Масштаб применяется при пересчёте
   пикселей эскиза, а не при печати.
3. **Три состояния достоверности.** `CONFIRMED` / `DERIVED` / `ASSUMED`.
   Домысленное — только на слой `ASSUMED` и в примечания.
4. **Модель не рисует.** Любая «умная» логика заканчивается на `model.json`.
   Черчение — детерминированный код.
5. **Труба не гнётся.** На листе только прямые участки и повороты 90°:
   `route.orthogonalize()` выполняется до раскладки, иначе рукописная дрожь
   превращается в изогнутые трубы. Скругление (отвод или гнутая труба) —
   это тот же поворот 90°, нарисованный дугой малого радиуса:
   `route.fillet_path(points, meta.fillet_mm)`. Диагонали допустимы только
   для тепловых трасс (режим `straight`).
6. **Ошибки не глотать.** Не удалось конвертировать DWG — задача `error` с
   текстом причины, а не «успех без файла».

## Стиль кода

* Python 3.11+, стандартная библиотека где возможно; внешние — только
  `ezdxf`, `matplotlib`, `Pillow`, `PyMuPDF`.
* Аннотации типов, `from __future__ import annotations`.
* Комментарии и тексты для пользователя — по-русски; имена в коде — английские.
* Никаких «магических» абсолютных путей: всё через `config.Settings`.

## Грабли, уже проверенные

* **BOM в JSON.** Файлы, записанные PowerShell 5.1 (`Set-Content -Encoding UTF8`),
  содержат BOM. Читать пользовательские JSON только как `utf-8-sig`.
* **Временные папки.** Системный `%TEMP%` может быть закрыт песочницей;
  тесты и кэш держать внутри проекта (`data/`, `.cache/`).
  `MPLCONFIGDIR` уже перенаправлен в `.cache/matplotlib`.
* **Open CAD Studio `--export`** понимает только `dwg/dxf/dwt` — PDF и PNG
  делает свой рендер, не просите у OCS PDF.
* **Повторное сохранение** в существующий DWG: файл удаляется перед
  конвертацией (иначе возможен диалог подтверждения).
* **Кириллица в DXF** — стиль `NS_GOST` с Arial; `Ø` рендерится нормально.
* **MULTILEADER в DXF от Open CAD Studio** — `entity.virtual_entities()`
  отдаёт proxy graphic с неверным масштабом (выноски «уезжают» за лист);
  реальную геометрию даёт
  `ezdxf.render.mleader.virtual_entities(entity, proxy_graphic=False)`.
* **У ветки MULTILEADER в `leaders[].lines[].vertices` — только острие.**
  Излом поводка лежит отдельно, в `last_leader_point`; `dogleg_length` и
  `dogleg_vector` задают короткий поводок к тексту. Если брать `targets`
  из proxy (`virtual_entities`), стрелка уезжает на излом: именно так в
  старых моделях gas/1–4 выноски перестали указывать на трубу. В модели
  для этого `callouts[].elbow` + `targets` = настоящие острия
  (`tools/enrich_callout_elbows.py`, проверка — `tools/callout_check.py`).
* **Полка под текстом — не всегда.** Если `elbow.y` у нижней части строки
  (квартирные схемы, фасад), её рисуем на всю ширину текста; если автор
  прицепил поводок к боку подписи (изометрия Валдая), полка короткая, у
  края, иначе линия проходит сквозь текст (`annotations._callout_shelf_start`).
* **Многострочная выноска — это `\n` в тексте, а не две выноски.** В старых
  моделях gas/1–4 переводы строк были склеены пробелом; обогащение
  возвращает авторские `\n` (`КранØ15\nИСØ15`), иначе полка считается по
  склеенной строке и становится вдвое длиннее.
* **Кегли подписей в DWG и на печати разные.** В эталонных DWG подписи
  схемы нарисованы высотой ~2,23 мм, а на печатном PDF те же подписи
  ≈4,26 мм (аннотативный масштаб ~1,9); легенда 4,49, итог 11,26.
  Если нужен вид «как на печати», кегли берутся из PDF
  (`model.meta.weld_height`, `callout_height`, `legend_height`,
  `summary_height`), а размеры штрихов (6 мм шов, 4,8 опора) — из DWG 1:1.
* **Скругление трубы рисуется одной полилинией.** Если рисовать дугу
  скругления отдельным `Arc`, на стыке с прямолинейным участком появляются
  ступеньки и «хорда» через поворот. `layout._draw_pipe_filleted` сэмплирует
  дугу точками и отдаёт один `Polyline`; при сэмплировании дуга должна
  начинаться со стороны текущей точки (обратный ход — отрицательным шагом).
* **Символы с поворотом.** В `draw_symbol` поворот применяется через `rot()`
  к КАЖДОЙ точке, иначе `rotation` молча игнорируется (так «краны» дважды
  оказывались поперёк трубы). Базовое направление `valve`/`valve_ball` —
  вдоль X, поэтому для вертикальной трубы нужен `rotation=90`.
* **Точки на трубе.** Середины штрихов швов и крестиков опор в исходных DWG
  смещены на 0,2–1,5 мм; перед черчением они проецируются на ось трубы
  (`snap_to_pipe` в `to_model.py`).
* **Выноски — настоящие MULTILEADER.** `scene.MLeader` → в DXF это
  `MULTILEADER` (стиль `NS_MLEADER` в таблице `MLEADERSTYLES`), в PDF —
  те же полки/ветки/стрелки. В CAD такая выноска правится одним объектом.
  Создаётся через `msp.add_multileader_mtext(style)` + `build(insert=Vec2)`.
* **Многострочная выноска — одна сущность.** «Переход / Ø25/20» это один
  MULTILEADER с текстом в две строки (в DXF \P), а не две выноски.
  Разносить по отдельным выноскам нужно только ветвящиеся (две стрелки,
  повтор узла) — например «Кран Ø15» / «ИС Ø15».
* **Подпись MULTILEADER привязана ВЕРХНИМ углом.** `context.mtext.insert`
  в эталонных DWG — это верхний левый (alignment=1) или верхний правый
  (alignment=3) угол текста, а не левый низ. Если взять его за низ
  (`Text.valign="bottom"`), все номера швов, квартиры и выноски уезжают
  вверх на высоту строки (≈4 мм) — так и «съезжает» вся схема. В модели
  для этого `welds[].label_align`, `callouts[].align` (+ `fixed: true`),
  `rooms[].label_align`; в сцене — `Text.valign`/`MLeader.valign`.
* **Опуск на квартиру — отдельный участок, а не продолжение магистрали.**
  Если `join_paths` протащит вертикальный опуск через весь путь, на стыке
  появится скругление «как отвод», а два соседних опуска склеятся в «вилку»
  с одной точкой внизу. Сначала выделяй вертикальные линии 9,6 мм
  (≈опуск) в свои `segments` с `kind="branch"`, магистраль склеивай
  отдельно; для изометрии `fillet_mm` = 0.
* **Тепловой план уже в мм листа.** `placement: absolute` в `build_scene`
  обязан идти через `IdentityTransform`, иначе исторический `Transform.pt`
  делает `y = y1 - p.y` и лист встаёт с ног на голову. Плюс
  `meta.no_orthogonalize = true`: `route.orthogonalize` для heat выбирает
  режим `iso` и крутит план на 13–14°.
* **Тепло: трубы — все линии слоя «Трубы», включая `short_lines`.** Старый
  извлекатель брал только длинные линии, и план терял короткие ветки/опуски.
  Склейка — только коллинеарных цепочек (8°, 0,7 мм), ветки/повороты остаются
  отдельными; слой `0` — штрихи символов, в трубы не идёт.
* **Задвижки тепла — из пар треугольников.** Две половинки с общим остриём,
  базы напротив, размер 3–5 мм → `elements[].type="valve"`, `size≈0,4`.
  Фильтры — 4-цикл коротких линий слоя «Трубы» (стороны 2–4 мм); их линии
  исключаются из труб, иначе ромб задваивается. Сейчас 184 задвижки и
  2 фильтра — проверить на ложные срабатывания (HANDOFF).
* **Дефекты тепла — маркеры + ведомость, а не 130 номеров.** На плане
  рисуется кружок 1 мм с точкой (номер не печатается), маркер прижимается к
  оси трубы (`layout._snap_to_pipe`, 8 мм); справа — «Ведомость дефектов по
  подъездам» (`annotations.defect_table`, `meta.defect_table_at`). Группировка
  по x-полосам подписей «N подъезд»; стояки в модели пока не выделены.
* **Легенда/ведомость по абсолютным координатам — план на всю ширину.**
  `layout.build_scene` при `legend_at`/`defect_table_at` не резервирует правую
  колонку и отрезает верхнюю полосу; иначе план сжимается влево и налезает
  на таблицу.
* **Аксонометрия фасада — `mode: "iso"`.** Такой лист собирается как схема
  ГОСТ (`resolve_mode` → `schematic`), но `route.orthogonalize` к нему не
  применяется: труба уже задана ломаной по осям 0°/±30°/90° в мм листа
  (`placement: absolute`, `meta.fillet_mm = 0`). Распознавание — блок
  `prompts.ISO_RULES`; проверки — `model._validate_iso` (наклонные участки
  есть, швы и опоры лежат на оси трубы, координаты absolute).
* **Знаки легенды — не элементы схемы.** Крестик «×-опора» в легенде
  эталона — обычная вставка блока опоры, а «14» — MULTILEADER с числом.
  В модель они попадать не должны: отсекай по расстоянию до трубы
  (>3 мм для опор) и по отсутствию засечки `СШ` рядом (для номера),
  иначе над легендой появляются лишние крест и номер.
* **Засечка шва — линия слоя `СШ`, а не конец поводка MULTILEADER.**
  Середина линии даёт точное положение и угол штриха; конец поводка — это
  полка у текста, она в 5–10 мм от трубы. Штрих при этом ставится ЦЕНТРОМ
  на ось трубы (в DWG он нарисован от трубы в одну сторону — если взять
  его середину как есть, засечка висит сбоку, а стрелка номера не попадает
  на трубу). После привязки к оси стрелка номера указывает ровно в центр
  засечки на линии трубы.
* **Подпись цепи — по месту автора, над линией, а не на ней.** В модели
  `chains[].text_at` (из `DIMENSION.text_midpoint`); без него текст ставится
  над линией на 1,5 мм в её собственной системе (`+n`), как рисует DIMENSION.
  Ввод в эталоне размечен так, что две цепи делят одну линию (сш 500/820):
  подписи разводит автор — сдвигать сами линии по offset не нужно, иначе
  весь ряд размеров уезжает «лесенкой». Если текст всё же попадает на
  чужую подпись, он сдвигается вдоль своей линии.
  **Важно: «вверх» — это направление самого текста, а не нормаль линии.**
  При `rotation=ang` текст растёт вдоль `u = (−sin ang, cos ang)`. Для
  участков, идущих справа налево (нормаль `n = −u`), смещение по `n`
  кладёт текст прямо НА линию — цифры перечёркиваются. Брать `u` и для
  подъёма на 1,5 мм, и для поиска свободного места.
* **Не глотать ошибки экспорта.** `scene_to_dxf` собирает неудачные
  примитивы и падает `DxfExportError`, а не молча теряет их: именно
  из-за `except: continue` MULTILEADER однажды исчезали из DWG целиком.
* **Толщины линий — только из таблицы слоёв.** `styles.LAYER_LW` (собирается
  из `LayerSpec`) — единственный источник и для DXF (BYLAYER), и для PDF
  (`render.DEFAULT_LW`). Пока в рендере был свой словарь, PDF рисовал все
  слои толщиной 0,25 и расходился с DWG. В схеме толщина трубы не зависит
  от диаметра (`lw=None` → по слою).
* **Кегли штампа на печати ×1,4** от высот DWG (аннотативный масштаб);
  узкие графы 10 мм остаются как есть, иначе не влезают в ячейку
  (`gost_sheet.STAMP_TEXT_SCALE`).
* **Текст в matplotlib** шире, чем в Arial: при тесной компоновке проверять
  предпросмотр, а не только DWG.

## Определение готовности

`tools/smoke_test.py` зелёный, `tools/api_test.py` доходит до `done`,
`tools/callout_check.py` (газ) и `tools/heat_check.py` (тепло) зелёные,
PNG просмотрен глазами, DWG открывается. Только после этого говорить
«готово».
